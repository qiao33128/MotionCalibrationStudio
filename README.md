# 运动控制 · 九点标定上位机

C# / WPF / .NET 8 自动化设备上位机示例：运动控制卡抽象层 + 九点标定解算 + 视觉对位闭环。

不接任何运动卡和相机，也能跑通全链路。

## 快速开始（无需任何硬件）

```bash
dotnet build MotionCalibrationStudio.sln
dotnet run   --project src/MotionCore.App
dotnet test  tests/MotionCore.Tests
```

启动后点右上角「一键自动演示（全链路）」，会自动跑完：初始化 → 九点示教 → 标定解算 → 三种模型对比 → 建立对位基准 → 故意偏移 → 自动对位收敛。

也可以命令行一键复现：`dotnet run --project src/MotionCore.App -- --demo`

## 目录结构

- `src/MotionCore.Abstractions` — 与厂商无关的抽象 + 通用编排（状态机、软限位、多轴同步、报警归一化，全项目一份）
- `src/MotionCore.Simulation` — 仿真卡 + 仿真相机 + Otsu 质心定位器
- `src/MotionCore.Calibration` — 九点标定数学核心、示教流程、视觉对位闭环
- `src/MotionCore.Vendors` — 正运动 / 固高 / 雷赛的 P/Invoke 原语
- `src/MotionCore.App` — WPF 上位机（MVVM，零第三方依赖）
- `tests/MotionCore.Tests` — 62 个测试

## 三个关键设计决策

### 1. 厂商差异只收敛在「十几个原语」上

雷赛 / 固高 / 凌华 / 正运动在函数名、参数语义、轴号起点、错误码上全都不一样，但真正有差异的只有「连接 / 使能 / 设参数 / 绝对定位 / 相对定位 / 点动 / 回零 / 停止 / 读状态 / 读写 IO」这几个动作。把它们定义成 `IVendorCardApi`，于是：状态机、等待到位、多轴矢量同步、软限位前置拦截只写一份；**仿真卡天然就是这个接口的一个实现**。换卡时业务层零改动。

### 2. 九点标定解的是「像素 → 机械」的最小二乘问题

相机随平台移动、Mark 固定不动，9 个位置各得一组 (机械坐标, 像素坐标)，据此拟合像素到机械的映射。三种模型都实现了：仿射 6 参数 / 单应 8 参数 / 二次多项式 12 参数。三个工程要点：

1. **Hartley 坐标归一化**：像素量级 ~1e2、毫米量级 ~1e1，不归一化条件数会差好几个数量级（归一化后实测条件数 1.076）。
2. **Householder QR 而非正规方程**：正规方程会把条件数平方。
3. **留一交叉验证选型**：RMSE 只说明拟合得好不好，留一误差才说明对没见过的点准不准。

同一次标定的实测对比：

| 模型 | 训练 RMSE | 留一 RMSE | 条件数 |
|---|---|---|---|
| 仿射 Affine | 0.004238 mm | **0.005782 mm** | 1.08 |
| 单应 Homography | 0.003771 mm | 0.005692 mm | 79.8 |
| 二次多项式 | **0.002929 mm** | 0.006745 mm | 51.2 |

二次多项式的**训练残差最好、留一误差最差** —— 这正是过拟合，程序会直接标出「疑似过拟合」并建议降级用仿射。只看 RMSE 是选不出正确模型的。

### 3. 对位是闭环，安全护栏比算法本身更重要

理论上一份精确的仿射模型一次补偿就能到位，但现场有反向间隙、伺服整定误差、镜头畸变残差与视觉噪声，所以必须做成「测量 → 补偿 → 复检」的闭环。

更要紧的是护栏：标定参数被改坏、或者视觉误识别到别的特征时，算出来的补偿量可能高达几十毫米 —— **初始偏差超过安全上限时直接拒绝移动**，宁可停机让人来看。

## 实测精度（仿真卡 + 仿真相机，无任何硬件）

- 标定 RMSE **0.004238 mm**，最大残差 0.006891 mm，质量 Excellent
- 反解出的像素当量 23.9997 / 23.9924 px/mm（真值 24），安装角 1.7305°（真值 1.7°）
- 对位：故意偏 0.75 mm → 1 次补偿后残差 0.005730 mm，收敛比 132:1
- 62 个测试全绿

## 界面

| 页签 | 内容 |
|---|---|
| ① 运动控制台 | 四轴状态表（指令/实际/跟随误差/使能/到位/回零/限位/报警）、点动、联动定位、回零、急停、报警复位、IO、报警注入演示 |
| ② 九点标定 | 标定画布（实测点/预测点/残差向量）、逐点残差表（超 3×RMSE 标红）、完整报告、三模型对比 |
| ③ 视觉对位 | 相机实时画面、三步演示、对位追溯 |
| ④ 架构说明 | 分层图与设计取舍 |

残差可视化是现场排查的关键：整体朝一个方向 = 系统偏差；某点单独跳出去 = 该点采集异常；呈环形 = 镜头畸变未被模型吸收。

## 换成真卡 + 真相机要改什么

代码里已经写好了三家的 SDK 调用原语（`src/MotionCore.Vendors`），上机时只需要：

1. 把 `x64/` 下的厂商 DLL 放到输出目录（`MotionCore.Vendors.csproj` 里留了拷贝目标）；
2. 用 `ZmotionCardApi` / `GoogolCardApi` / `LeadshineCardApi` 替换 `SimulatedCardApi`，构造 `MotionControllerBase` 的子类；
3. 相机侧把 `IVisionLocator` 换成基于 Halcon / OpenCV 的实现，`ICamera` 换成实际取流实现。

`AlignmentService`、`NinePointTeachingService`、标定解算、WPF 界面**一行都不用改**。
