# 运动控制 · 九点标定上位机 —— 技术方案

## 1. 背景与目标

非标自动化设备（光学模组 AA 胶合、贴合、点胶、AOI 检测）普遍是这样一个结构：**运动控制卡驱动多轴平台，工业相机随平台移动，通过视觉找 Mark 点，再把像素偏差换算成机械补偿量做对位。**

这类设备的软件开发有两个绕不开的难点：

1. **运动控制卡品牌杂**：雷赛、固高、凌华、正运动各有各的 SDK，函数名、参数语义、轴号起点、错误码全不同。项目换卡、或者同一台设备上混用两家卡，就意味着一大堆重复代码和不同的坑。
2. **九点标定看着简单，做扎实很难**：原理人人会讲，但现场踩的坑集中在 —— 坐标量级差异导致方程病态、用正规方程解导致精度丢失、模型参数选多了过拟合、标定做完不知道准不准、视觉误识别导致补偿量离谱直接撞机。

本方案的目标是给出一个**可落地、可验证、可上机**的完整实现，并且做到**在没有硬件的情况下端到端可跑、可测**。

## 3. 运动控制卡抽象层

### 3.1 差异收敛：《IVendorCardApi》只定义「原语」

```csharp
public interface IVendorCardApi : IAsyncDisposable
{
    string Name { get; }                       // "正运动 ZMC" / "固高 GTS" / "雷赛 DMC"
    bool IsConnected { get; }
    IReadOnlyList<AxisId> Axes { get; }

    Task<int> ConnectAsync(string address, CancellationToken ct);   // 返回厂商错误码
    Task<int> DisconnectAsync(CancellationToken ct);
    Task<int> EnableAxisAsync(AxisId axis, bool enable, CancellationToken ct);
    Task<int> HomeAxisAsync(AxisId axis, double velocity, CancellationToken ct);
    Task<int> MoveAbsoluteAsync(AxisId axis, double position, MoveProfile profile, CancellationToken ct);
    Task<int> MoveRelativeAsync(AxisId axis, double delta, MoveProfile profile, CancellationToken ct);
    Task<int> StartJogAsync(AxisId axis, MotionDirection direction, double velocity, CancellationToken ct);
    Task<int> StopAsync(AxisId axis, bool emergency, CancellationToken ct);
    AxisStatus ReadStatus(AxisId axis);
    bool ReadInput(int index);
    bool ReadOutput(int index);
    Task<int> SetOutputAsync(int index, bool value, CancellationToken ct);
    string GetErrorMessage(int errorCode);
    void ClearError();
}
```

**设计要点：返回值统一是「厂商错误码」而不是抛异常。** 因为厂商 SDK 的错误码语义只有各自适配器清楚，抽象层负责把它翻译成项目统一的 `MotionException`。这样上层永远不会看到「雷赛的 -7」和「固高的 0x1002」这种原始码。

### 3.2 通用编排：《MotionControllerBase》

所有厂商都绕不开的逻辑集中在基类里，**只写一份**：

| 能力 | 说明 |
|---|---|
| 状态机 | `Disconnected → Initializing → Ready → Moving / Hold / Alarm / EmergencyStop` |
| 状态轮询 | 后台定时（默认 30ms）读状态并通过 `StatusUpdated` 事件广播 |
| 等待到位 | `WaitInPositionAsync`：到位 + 速度归零才算完成，带超时与 `ActualPosition` 精确落点 |
| 软限位前置拦截 | 目标超出软限位**在发指令之前**就抛 `MotionSoftLimitException`，控制器状态不会被切到报警 |
| 多轴同步 | `MoveAbsoluteAsync(MotionPose)`：同时下发各轴后统一等待到位（矢量运动而不是串行） |
| 回零 | `HomeAllAsync` 依次回零 + 回零后重新使能（部分卡回零后会掉使能） |
| 报警归一化 | 厂商错误码 → `MotionAlarm{Category, Severity, Code, Message, Advice}` |
| 点动 | `StartJog` / `StopJog` 成对，避免"按住走、松开不停" |

**为什么把软限位放在上位机而不是只依赖控制器？**  
控制器的软限位触发后一般要清报警、重新使能，操作工不一定知道怎么恢复。上位机提前拦截，是最省事、最不容易出事故的做法。控制器侧的软限位仍然要设，作为第二道防线。

### 3.3 仿真卡是「接口的一个实现」，不是 mock

这一点是整个方案能"无硬件跑通"的根基。`SimulatedCardApi` 不是打桩返回固定值，而是一个**行为模型**：

- **梯形速度曲线**：真实的加速段 / 匀速段 / 减速段，行程不足时自动退化为三角形曲线（`TrapezoidalProfile`）；
- **跟随滞后**：实际位置滞后指令位置约 3ms，于是「跟随误差」这一列在界面上是有意义的数字，不是 0；
- **定位噪声**：落点带 0.004mm 量级随机误差，与真实丝杆平台重复定位精度同量级 —— 否则标定残差恒为 0，测试就失去意义；
- **软限位 / 急停 / 报警**都真实参与状态机流转。

因此**所有上层测试都是有意义的**：如果标定算法写错了，仿真卡不会替它掩盖。

## 4. 九点标定

### 4.1 建模：像素 → 机械

相机随平台移动、Mark 固定不动。平台走到 9 个位置，Mark 在图像里相应移动，于是每个位置得到一组 (机械坐标, 像素坐标)。标定的目标不是"像素→机械"本身，而是**反解出「要让 Mark 落在指定像素，平台该走到哪个机械坐标」**：

```
g(p) = Mark − M⁻¹ · (p − center)
```

`M` 就是待拟合的映射矩阵（像素/毫米量级），`center` 是图像中心。三种模型：

| 模型 | 参数 | 适用 |
|---|---|---|
| 仿射 Affine | 6 | 相机正常安装（平移+旋转+各向异性缩放+剪切），抗噪最强，**首选** |
| 单应 Homography | 8 | 相机有安装倾角、标定面与运动面不平行 |
| 二次多项式 | 12 | 视野大、镜头径向畸变明显时更准，但也最容易过拟合噪声 |

三种模型统一实现为 `ICalibrationModel`：给一组像素点就能算出机械坐标，并提供 `ToCoefficients()` 用于持久化。

### 4.2 三个必须做对的工程细节

**① Hartley 坐标归一化（必做）**

像素坐标量级 ~1e2（320, 240），毫米坐标量级 ~1e1（12.5）。直接代入设计矩阵，两列的量级差 10 倍以上，条件数会被放大好几个数量级。

做法：对每组点先做平移+各向同性缩放 —— 质心移到原点、平均距离归到 √2，解完之后再把变换合回去（`T⁻¹ · A · S`）。

效果可验证：归一化后实测条件数 **1.076**；如果关掉归一化会直接飙升若干个数量级。测试 `LinearAlgebraTests.归一化后的九点标定设计矩阵条件数应接近一` 就是守护这件事的。

**② Householder QR 而不是正规方程（必做）**

用正规方程解最小二乘，需要先算 `AᵀA`，相当于把条件数**平方**。现场表现为：数据看着挺好，解出来的参数抖得厉害。

工程上还有个额外理由：**QR 能算 rank，正规方程不能。** 标定点共线（操作工手抄错、或者只标了一条线）时，QR 分解会出现极小的对角元，可以明确抛出"设计矩阵秩亏"而不是返回一堆垃圾参数。

**③ 留一交叉验证（选型必做）**

RMSE 只说明**拟合得好不好**，不说明**对没见过的点准不准**。参数更多的模型训练残差一定不会更差，所以只看 RMSE 必然选到最复杂的模型。

留一验证（LOOCV）的做法：每次留出一个点，用其余 8 个点重新标定，再预测被留下的那个点，最后取平均误差。本项目的实测结果就很典型：

| 模型 | 训练 RMSE | 留一 RMSE |
|---|---|---|
| 仿射 | 0.004238 mm | **0.005782 mm** |
| 单应 | 0.003771 mm | 0.005692 mm |
| 二次多项式 | **0.002929 mm** | 0.006745 mm |

二次多项式训练最好、留一最差 —— 程序据此标记「疑似过拟合」并建议降级用仿射。

### 4.3 质量评估：RMSE 之外还要看什么

| 指标 | 现场含义 |
|---|---|
| RMSE / 平均误差 / 最大误差 | 精度本身 |
| 条件数 | 标定点布局是否退化（> 1e6 报警） |
| 留一误差 | 泛化能力；与训练 RMSE 差距大 = 过拟合 |
| 逐点残差 | 单个点超 3×RMSE 就标红 —— 那是"这个点采坏了"，不是模型不好 |
| 反解出的像素当量 / 安装角 | 与相机镜头标称值对照，能立刻发现标定整体跑偏 |

最后一条很有用：把反解出来的像素当量（本项目实测 23.9997 / 23.9924 px/mm，真值 24）和相机安装角（实测 1.7305°，真值 1.7°）直接打到报告里，现场一眼就能判断标定是不是可信。

## 5. 视觉对位闭环

### 5.1 算法

```
g(p) = Mark − M⁻¹ · (p − center)

第 1 次：实际位置 P₀ ──拍照──▶ Mark 像素 p₀ ──g()──▶ 目标位置 P₁ ──移动──▶
第 2 次：实际位置 P₁ ──拍照──▶ Mark 像素 p₁ ──g()──▶ 目标位置 P₂ ──移动──▶
...  直到 |g(pᵢ) − Pᵢ| ≤ 公差
```

**为什么要做闭环而不是一次到位？** 理论上一份精确的仿射模型一次补偿就够了，但现场存在反向间隙、伺服整定误差、镜头畸变残差、视觉噪声 —— 单次补偿的残差通常在几微米到几十微米，达不到 AA 工艺要求的水平。闭环后实测**1 次补偿即收敛到 0.0057 mm，收敛比 132:1**。

### 5.2 安全护栏（比算法更重要）

```csharp
if (measurement.RelativeErrorMagnitudeMm > options.MaxInitialErrorMm)
{
    return AlignmentResult.Refused($"初始偏差 {error} mm 超过安全上限 {limit} mm，已拒绝补偿移动");
}
```

**这条判断是整个项目里最重要的三行代码。** 标定文件被改坏、或者视觉误识别到基板上的其他圆形特征时，算出来的补偿量可能高达几十毫米，直接执行就是撞机。宁可停机让人来看。

此外还有：
- 迭代上限（默认 4 次），不收敛就报失败而不是无限循环；
- 每次迭代都记录**像素坐标、平台位置、补偿量、残差、匹配置信度**，形成可追溯的对位记录；
- 置信度低于阈值直接判定定位失败，不进入补偿流程。

### 5.3 视觉定位实现

`BlobCentroidLocator`：**Otsu 阈值分割 → 连通域标记 → 面积/圆度过滤 → 灰度加权亚像素质心**。

- 灰度加权质心（而不是二值质心）能把定位精度从 ±0.5px 提升到 ±0.05px 量级，这是"九点标定"能不能做到微米级的前提；
- 面积与圆度过滤掉噪点和异物，避免误识别；
- 置信度由「面积接近期望值程度 + 圆度」合成，供上层做二次判断。

### 5.4 标定文件

CSV 明文，**可读、可 diff、可用 Excel 打开**：

```
# MotionCore Calibration File v1
Model,Affine
Normalize,True
ExcellentRmseMm,0.002
AcceptableRmseMm,0.010
Points
Label,ImageU,ImageV,MachineX,MachineY
P11,394.2071,170.2095,9.5000,-10.2500
...
```

现场排查时可以直接把文件发给供应商，也可以手工核对某个点有没有采错。载入时用文件里的原始点**重新解算**，而不是直接相信写进去的系数 —— 这样系数和点永远自洽。

## 7. 上机改造路径

| 步骤 | 动作 | 工作量 |
|---|---|---|
| 1 | 厂商 DLL 放入 `x64/`（工程已留拷贝目标） | 0.5 天 |
| 2 | 用 `ZmotionCardApi` / `GoogolCardApi` / `LeadshineCardApi` 替换 `SimulatedCardApi` | 0.5 天 |
| 3 | 相机侧：实现 `ICamera`（取流）与 `IVisionLocator`（接 Halcon/OpenCV 或直接调 `BlobCentroidLocator`） | 1~2 天 |
| 4 | 按机型配置轴数、软限位、回零方式、点动速度 | 0.5 天 |
| 5 | 现场：示教 → 标定 → 试对位 → 看残差报告判断是否可投产 | 0.5 天 |

**上层业务代码（示教流程、标定解算、对位闭环、界面）一行都不用改** —— 这是分层的价值。

## 8. 可扩展方向

- **标定点位可配**：现在固定 3×3 九点，`NinePointTeachingOptions` 里已支持自定义顺序与行程；扩到 5×5 / 12 点只需改配置。
- **多相机**：`IVisionLocator` 与 `ICamera` 都是接口，多相机只需注册多实例。
- **带旋转轴的对位**：`MoveProfile` 已支持旋转轴（度/秒），R 轴参与 `MotionPose` 后即可做角度补偿。
- **标定漂移监控**：定时拍一次标准 Mark，用现有 `CalibrationResult` 评估残差是否变大，超过阈值提示重新标定。
- **接 MES**：标定结果与对位记录都是结构化数据，可直接落库做设备能力（Cpk）追溯。
